# Pipekit v2 (alpha)

> **Status:** alpha — runs alongside v1. v1 skills (`/launch`, `/branch`, `/start-session`, `/end-session`) still work. Switch back at any time.

## What v2 is

A radical simplification of the daily Branch → Work → Ship → Close loop:

- **2 skills:** `/work`, `/verify`
- **5 deterministic scripts** (in `bin/pk`): `next`, `branch`, `ship`, `done`, `status`, plus utilities `file`, `verify`, `promote`
- **2 hooks:** journal append on Stop, post-commit hook for branch journal
- **Linear is the source of truth.** No `NEXT.md` mirror. No `pending-next-md.json` cache.
- **Recovery = rerun the command.** Every script is idempotent against Linear+git ground truth.
- **Per-project config** in `method.config.md` (v2 keys, additive to v1):
  - `backend: vbw | native` — `/work` dispatches accordingly
  - `integration_branch: dev | main` — `pk ship` PR target
  - `promote_to_main: true | false` — whether `pk promote` is in the daily flow
  - `require_qa_review: true | false` — whether `/verify` runs by default
  - `ship_environments` — for multi-env deploy (Piper-style)

## Coexistence with v1

v2 commands have non-colliding names. You can use both during the alpha:

| Step | v1 | v2 |
|---|---|---|
| What's next? | `cat NEXT.md` | `pk next` |
| Quick status | `/linear-status` | `pk status` |
| Branch | `/branch --linear RS-XX` | `pk branch RS-XX` |
| Plan + work | `/launch RS-XX --auto` | `/work RS-XX` |
| Verify | `/vbw:vibe --verify` | `/verify` |
| End session | `/end-session` | `/pk-exit` |
| Open PR | `/launch RS-XX --close` | `pk ship` |
| Cleanup | `/branch finish RS-XX-…` | `pk done` |
| Promote dev → main | `/g-promote-main` | `pk promote` |

## How to test in a consuming project

```bash
cd ~/Projects/<project>
./scripts/sync-method.sh v2.0.0-alpha.1
# Now bin/pk + skills/work + skills/verify are present alongside v1
```

Pick one issue, run it through v2 commands. If anything fails, fall back to v1 — both still work.

3. After 2 weeks: delete `deprecated/`.
