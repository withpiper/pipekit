# A/B trial: /work v4.32.0 vs v4.34.0 on SiteLine PIPER-412

Pre-registered 2026-09-02, before either arm runs. Nebula.

## Question

Does the v4.34.0 `/work` (plans inline, executes on the saved `pk-execute` workflow) produce a
better or cheaper first pass than the v4.32.0 `/work` (prose-driven, one Agent per task) on a
Standard-tier issue with a passing Light Spec? "Removal is a hypothesis": v4.34.0 also stripped
~260 lines of prescriptive prose, so a loss here is a finding about the rewrite, not just the workflow.

## Subject

PIPER-412 — Excel export: admin-block base is a baked literal — live-formula it.
Approved, `tier:standard`, Light Spec Pass 9/10, no DB change, no external service.
Seven AC, one of which (real-Excel forced recalc, AC6) is a manual UAT step outside the trial.
Deterministic oracle: `python3 scripts/test-budget/check-export.py <internal> <client>` on fresh
ULT-A artifacts — all suites pass, admin base still 19,200, COGS still 4,000, STABILITY lists the
new formula cells.

## Metrics (in precedence order)

1. **AC coverage** — blind judge, per AC1–5,7: met / partial / unmet with diff line evidence.
2. **First-pass gate** — did `/verify` (auto-rollover) pass on the first run with zero manual fixes;
   count gate failures and operator interventions.
3. **Oracle** — `check-export.py` result on the arm's branch (run by me after both finish, same
   fixtures for both).
4. **Tests authored** — new/changed assertions in the diff (deterministic count).
5. **Atomic commits** — commit count, each subject one sentence + scoped; any commit touching more
   than one task's files counts against.
6. **Cost** — tokens from the session transcript + its `subagents/` dir (deduped by message id),
   split input / output / cache-create / cache-read; plus the `/cost` line the operator pastes.
7. **Wall-clock** — first to last transcript timestamp.

Decision rule: B ships if it is ≥ A on (1) and (2) and not more than 20 % worse on (6). If B loses
on (1) or (2), A ships and the loss feeds a v4.36.0 revision of the skill, not a wholesale revert.
Ties on (1)–(3) go to whichever wins (5), then (6).

## Blind judge

Fresh subagent on the plan-review tier (`opus` / `xhigh`). Input: the Light Spec verbatim, two
patches labeled X and Y (coin-flip mapping written to `temp/ab-412-mapping.txt` BEFORE the judge is
spawned), the oracle output for each. Excluded from its view: branch names, `.pk-work/`, SUMMARY
files, commit messages, session logs, any Pipekit-owned path. Prompt: find where each patch fails
the contract; never asked which is "better" until after per-AC scoring.

Decisive finding on the final cut (both judges, verified by me in the patches): B's admin cells never round while
every cached value is `MoneyCore.round2`-ed — B's own fixture pins `L*H` with cached `14.38` where `57.5 × 0.25 =
14.375`, a forced-recalc drift AC6 forbids and the ULT-A oracle cannot see (ULT-A is cent-exact). B also emits
`C*F*K` / `C*D*F`, adding the multiplier cell the spec's Decision (`qty × rate`) and `deriveAdminOut` exclude.
A's final patch carries `ROUND(...,2)` everywhere and reproduces the engine to the cent. At the `/work` cut A had
the same unrounded, multiplied shapes as B — the parity came from A's two opus adversarial cycles in `/verify`,
not from `/work`. B's single sonnet adversarial cycle (opus was rate-limited) raised neither defect.

What the judges hold against A (all three): tests are source-text regexes (67 `toMatch`, zero builder execution)
that cannot go red on a behaviour change; a `ROUND→RND` shim in the checker's evaluator where the spec expected
none; a literal-base fallback that degrades to `console.warn`; and at the `/work` cut a missing lazy-load pin bump
(deterministic gate red — A's first `/verify` gate run exited 1 on `tests/lazy-load-pins.test.js`; verify bumped it).
What they hold for B: a real vm-sandbox harness that drives both builders, both doors, the masked payload and a
name-collision probe (9 of 12 tests red against the pre-fix exporter); simpler, order-robust composition; the pin
bump handled inside `/work`. Against B beyond AC6: the checker gains no admin assertions (a full revert would still
report 1940/0), a stale test-file docblock, the `4000/40000` literal memorised as a string.

**PIPER-412 ships from arm A** (`feature/PIPER-412-excel-export-admin` @ `c7bc5a399`, sentinels stamped): B loses
metric 1 on the final cut, and the rule says A ships. Loser branch/worktree: `feature/PIPER-412-excel-export-admin-b`.

**Harness reading (feeds v4.36.0, not a revert):** the `/work` variable itself did not lose — on the cut that isolates
it, the blind judge preferred B for tests and gate hygiene with equal AC coverage, on sonnet/medium agents against a
Fable-inline incumbent. The quality gap that decided the ship was made in `/verify`: opus adversarial ×2 (A) vs a
sonnet fallback ×1 (B). Cost is the open problem: v4.34.0's main-session planning + integration alone matched the
incumbent's whole inline execution, and the workflow agents came on top.

Follow-ups for v4.36.0:
1. `/verify`: never grant PASS on a downgraded adversarial tier; a rate-limited opus run must retry or block, not
   fall back to sonnet and report PASS + flag. (Anchor: arm B missed cent parity and the multiplier.)
2. `/verify`: a claim in the closing message must exist in `evidence.txt` at the verified sha — arm B cited the
   pre-pause ULT leg after its scratchpad was wiped and never re-ran it.
3. `/work`: cut the main-session cost (98k output before any agent ran) — measure planning prose vs grounding.
4. `/work`: the plan should carry the lazy-load-pin / manifest step when a pinned file changes (B's T5 did it
   post-workflow; A's did not) — a deterministic check, not prose.
5. Model Policy revisit (Ethan's open item): sonnet/medium execution produced the same product shapes as
   Fable-inline here; the tier that mattered was the adversarial reviewer's. Keep execution cheap, keep review on opus.
