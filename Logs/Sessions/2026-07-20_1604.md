## Decisions / findings (worth remembering)

1. **Finding 1 was a real design defect, not noise.** `cmd_ship` reused one `force` variable for two independent sentinel gates (v2.7 verify + v4.17.0 secgate). Since `--force` is muscle-memory for routing around a stale/rolled-over *verify* sentinel, it silently also waived an armed `/security-gate` review. Fix = split the flag; the safer default falls out (plain `--force` now **blocks** on a security-gated project with no HEAD-matching secgate sentinel).
2. **The env layer was already decoupled** (`PK_VERIFY_BYPASS` / `PK_SECGATE_BYPASS` are separate) — only the CLI flag had collapsed the two. So the split just brings the flag in line with what the env vars already did; consistent with `pipekit-security.md` "flag granularity should match blast radius."
3. **The twin gate is NOT double-duty** — the reviewer scoped Finding 1 to ship, and that's correct: `pk promote --force` waives only prod-ready; the UAT-state check has its own `--confirmed`. No change needed in `cmd_promote`. (Precision the reviewer didn't state but which mattered for confirming the fix was complete.)
4. **`case` full-string matching** means `--force-secgate` doesn't collide with the `--force)` arm even though it's a prefix — but I ordered `--force-secgate)` first anyway for readability.
5. **Consumer gotcha for Finding 2:** `templates/ci/migration-drift.yml` is a *manual copy* into `.github/workflows/` — `sync-method.sh` only touches skills/sop/templates/method.md, never workflow files. So fixing the template round-trips to future adopters, but any consumer that already copied it must hand-apply the `env: BASE_REF` edit locally. Gave the user a ready-to-paste command for the SiteLine session.
6. **GitHub auto-deletes the PR branch on merge** in this repo — the remote `--delete` push failed with "remote ref does not exist"; `git remote prune origin` cleaned the stale tracking ref.
