## Decisions / findings (worth remembering)

1. **Subagent context inheritance is total on this harness.** Every Agent-tool probe — regardless of agent type or pinned model tier — received the full claudeMd block, MEMORY.md, skills roster, and git status. Design consequence: there is no subagent-only delivery channel; the only lever on rule cost is total always-on size. Evidence + redirected design: `resources/item-c-premise-check.md`.
2. **The boundary that keeps spawn prompts and rules from double-billing:** spawn prompts carry task-specific behavior (e.g., the permission-denial-stop instruction, which lives in no rule); rules carry always-on constraints; nothing lives in both. The Skills_SOP precedent survives *because* it respects this — generalizing it into guard-rail blocks would have violated it.
3. **pipekit-the-repo's own `.claude/` is fully gitignored** — the `.claude/rules/*` copies are untracked local mirrors; `templates/rules/` is the only canonical, tracked source. Refresh mirrors with `cp` after editing templates; don't try to commit them.
4. **Grep commands with pipes don't survive markdown table cells** (GFM `\|` escaping inside code spans is renderer-fragile and corrupts copy-paste). The migrations invariants went out as bullets instead of the drafted table for exactly this reason.
5. **Discipline-rule trim was dropped deliberately**: demand-loading the Expanded Plan Gate format (~0.6kB) would need a new SOP home for one block — overhead exceeding the win. Same call for `pipekit-security.md`. Rightsizing now hits diminishing returns; remaining always-on weight is enforceable constraint or incident anchor.
6. **User decision:** ship v4.23.0 without Item C rather than hold for the redirect — the handoff's own "split if either balloons" contingency; then green-lit the trim as v4.24.0 ("if it is really helpful" — assessed yes, with the discipline/security candidates dropped).
