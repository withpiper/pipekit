## Decisions / findings (worth remembering)

1. **The handoff's own diagnosis on its decision 2 was wrong, and checking it changed the fix.** It argued `pipekit-discipline.md`'s "escalate after three" existed and wasn't enough, so the gap was the trigger definition. `skills/verify/SKILL.md:371` says otherwise in as many words: that rule governs cycles *within* one `/verify` run and "belongs to a future multi-cycle iteration-loop skill." Nothing governed the same issue re-verified round after round — a documented hole, not a weak trigger. So the drift signals went into `/verify` (demand-loaded, fires at the moment of the round) rather than the always-on rules, which v4.24.0 had just spent a release trimming.

2. **`/spec-preflight` was the wrong home for the split heuristic, for a firmer reason than the handoff's.** Its contract is read-only *empirical* checks against reality. "Should this be two issues?" is a design judgment no filesystem check resolves; putting it there dilutes what preflight means. The judgment surface that *can* gate it is the Spec Review Agent — hence v5.5's Bundling Rule, scoped to Blocking at heavy tier only, since nearly every feature spec touches both schema and client and an unconditional block would make the agent noise and get routed around.

3. **The handoff would have silently dropped a lesson.** It proposed upstreaming sections 1–2 of SiteLine's local rule while instructing that the whole file be deleted once upstream landed. Section 3 (line-based `grep` can't match a claim that wraps a line; measure regressions against the integration branch, not your own worktree) was never proposed. Upstreamed it as `pipekit-tooling.md` § "The Verification Method Must Be Able to See the Failure" before deleting anything.

4. **`${PIPESTATUS[0]}` is empty in zsh, and Claude Code's Bash tool runs zsh.** zsh spells the array `pipestatus`, 1-indexed. `/verify` Step 3's `run_gate_command` read `${PIPESTATUS[0]}`, got empty, printed `exit: 0` for every command, and `return $rc` degenerated to returning the *printf's* status. `GATE_RC` never left 0. `evidence.txt` preserved the false `exit: 0` as the durable record, and since `/verify` PASS writes the sentinel `pk ship` hard-gates on, a failing suite could ship. Reproduced before fixing (`exit 7` → `GATE_RC=0` zsh / `7` bash), fix re-tested in both. `tier:quick` was never affected — it runs the gate unpiped.

5. **CI caught a bug that local runs structurally could not, and the reason is itself the lesson.** The conflict warning first read its integration branch via `pk config …` — shelling out to whatever `pk` is on PATH rather than the in-script `pk_integration_branch`. It passed locally *only because* the installed `pk` is a symlink into SiteLine's working tree; on a clean runner no `pk` exists, the substitution died under `set -euo pipefail`, and the entire warning was suppressed. Line 1286 was the sole self-call in `bin/pk`. A structural smoke test now asserts there are none, because a behavioural test can only catch this on a machine without `pk` installed.

6. **Ignoring `.claude/` by directory was the mistake — it holds three different kinds of thing.** Generated mirrors (`skills/`, `rules/`, `agents/`), genuinely-unique config (`settings.json`), and personal state (`settings.local.json`). The blanket ignore meant a fresh clone had the commit-format hook *documented in CLAUDE.md as enforcement* but absent in fact, and it let the mirrors rot unobserved: 25 of 25 skills drifted, six missing, `.claude/skills/verify/SKILL.md` 157 lines behind and still carrying finding 4's bug.

7. **Correction to my own earlier answer on that question.** I initially recommended tracking `hooks/` and `agents/` as untracked-and-unique. They are not — `agents/` and `templates/hooks/` are already tracked at their canonical paths, and the `.claude/` copies are just more mirrors. Only `settings.json` was genuinely unique. Checking before acting changed the shape of the fix.

8. **Vercel will not dissolve the conflicting-PR gap.** GitHub cannot build `refs/pull/N/merge` for a conflicting PR, so it dispatches zero `pull_request` workflows — a GitHub Actions merge-ref mechanic, independent of where the app deploys. A preview that builds from the branch head rather than the merge ref will keep posting a green check on a PR whose suite never ran, which makes the board read *more* settled, not less.

9. **piper's `check-generated-types` is pre-existing red.** It regenerates types from the live Supabase project and diffs the committed `src/lib/siteline.types.ts`. Confirmed by checking #545 — the previous sync — which failed identically and was merged anyway. The v4.26.0 sync touches zero `.ts` files.
