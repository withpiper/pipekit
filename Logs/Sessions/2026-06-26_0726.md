## Decisions / findings (worth remembering)

1. **The `pk done` worktree guard was structurally defeated.** It gated on `[ "$root" != "$wt_path" ]`, but `pk_repo_root()` is `git rev-parse --show-toplevel`, which from *inside* a linked worktree returns the worktree itself → `root == wt_path` → guard skipped exactly the run-from-inside case it exists to catch. And `--merge` ran *above* the guard, so the PR merged before the (skipped) refusal. Fix: un-gate (the inner `pwd -P` check is the real signal), move the guard above `--merge`, point the refusal at the actual parent repo (first `git worktree list` entry, not `$root`).
2. **Stale local main bit me again** — exactly the documented lesson. I assessed release state against a local `main` at 3834453, staged a v4.6.1, then discovered `origin/main` had advanced to v4.7.0 (VBW retirement, PR #140) mid-session. Had to drop the release commit, rebase the fix onto v4.7.0, re-cut as v4.7.1. **Always `git fetch` + check `origin/main` before numbering a release.**
3. **Priority, not difficulty, should route Triage state.** `/linear-hygiene` routed Triage→Needs-Spec only for `tier:*`-labelled issues, burying important-but-unsized follow-ups in Backlog (invisible to `pk next`). Changed to route by resolved priority — *and coupled it with* flipping the priority catch-all floor `none → Low`, so "Normal+ → Needs Spec" means "a signal said this matters," not "wasn't explicitly downgraded." Without the floor flip the cut floods Needs Spec.
4. **`pk next` ordered by `updatedAt`, not priority** — so even after routing important items into Needs Spec, the *most* important wasn't on top and `.[0]` (the suggested next action) was the most-recently-touched. Linear's `orderBy` enum has no priority field → sort client-side in jq (None/0 must remap to last, not first).
5. **Linear blocked-by direction** (for dependency-aware `pk next`): a `blocks` relation is `issue` blocks `relatedIssue`; an issue's blockers come from its `inverseRelations` (type `blocks`, the `.issue` side), satisfied iff Done/Canceled. Verified against Linear's published schema + recipes, **not** a live introspection (pipekit has no Linear; SiteLine's `op` wasn't authenticated in the tool shell). Helper built fail-safe so a direction error is at worst a cosmetic mislabel.
6. **Piper disables GitHub auto-merge** (deliberate prod human-gate); SiteLine allows it. Saved as memory `consumer_merge_policies`. Don't circumvent Piper's gate — open the PR, hand the merge to the user.
7. **Made each load-bearing jq filter a pure, sourced-testable helper** (`pk_issues_priority_sort`, `_group_render`, `_annotate_blocked`, `_flat_render`, `pk_first_ready_id`) rather than inlining — the smoke suite tests them with sample JSON, no network. Caught two real bugs this way: orphans not sinking last (name-tie on `(`), and `def label` being a jq reserved word.
