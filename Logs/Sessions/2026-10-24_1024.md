## Decisions / findings (worth remembering)

1. **Most rules are already default behaviour.** The probe A/B scored old rules 26/26, cut rules 25/26 and no rules 22/26. Only three probes depended on rules at all: cmux RPC, destructive-action confirmation and MCP-applied migrations. Short direct probes can't see dilution in long sessions, so going from 3,750 toward 3,000 needs a mid-task, long-session test first.
2. **A fresh reviewer found 27 dropped conditions in the first cut.** Two of them were errors I introduced: an unconditional "never `&`", and a README overclaim that every `pipekit-*.md` file is sync-owned. A mechanical ID check alone would have shipped those.
3. **The rules README stays auto-loaded but cut to about 150 words.** Its one load-bearing instruction is "don't edit the sync-owned files, write a companion file". Moving it out was the user's worry and was rejected.
4. **`paths:` frontmatter scoping works.** Verified headless: a scoped rule loaded only after a matching file was read.
5. **Area is chosen for the issue's own work (user's call).** The parent's Area is only a starting guess. The exception is `/work`'s risk-fallback follow-up, which keeps the parent's Area. The Area-definitions table was dropped; it failed its bar on 2026-09-27. A patch of the draft was saved to the session scratchpad, which is ephemeral.
6. **Consumer syncs silently revert in-place script fixes.** Diffing against the stock previous release caught SiteLine's `check-*` scripts; now fixed upstream. Piper's hand-edited runbook line was the same class of problem; the runbook now names `method.config`'s Migration dir.
7. **The Claude reviewers on both consumer PRs misread one diff backwards.** They claimed the `§ no silent caps` citation was still present, but the sync had removed it. Verify reviewer claims against the file before acting.
8. **The commit hook parses a second `-m` as the subject.** Use `-F` heredocs for multi-paragraph messages.
