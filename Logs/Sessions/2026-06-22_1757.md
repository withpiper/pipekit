## Decisions / findings (worth remembering)

1. **`/security-gate` has no seam between `/verify` and `pk ship`** — `/verify` auto-invokes `pk ship` on clean Pass, so a standalone step there is silently skipped. The adversarial DOUBT pass caught this as the decisive bug; fix was to run the gate from `/verify` Flag check F (mirroring the migration self-review), where a category match pauses auto-ship. Unlike `/prod-ready`, whose seam (`pk promote`/`pk done`) is genuinely manual.
2. **v4.5.0 parser is backward-compatible by design** — `^([iI][0-9]+\.)?[pP][0-9]+\.` accepts both `I{N}.P{N}.` and bare `P{N}.`. This is what let the rollout avoid a breakage window: sync consumers first (parser accepts both), then rename.
3. **Stale local checkout masquerades as a bug** — Piper's `pk status` showed "all projects done" after the rename; cause was the local working tree wasn't `git pull`ed after #472 merged, so it ran the old v4.4.0 parser against the new names. Always pull the consumer integration branch after merging its sync before verifying with local `bin/pk`. (Re-anchors the same lesson from 2026-06-10.)
4. **Consumer PR queue should be consolidated, not stacked** — the held v4.4.0 sync PRs (#444/#471) were folded into the v4.5.0 sync PRs (#446/#472) so the user merges one PR per consumer, not a dependency chain. Closed #444/#471 as superseded.
5. **Cross-workspace Linear writes need each workspace's token** — SiteLine's is plain `.env` (direnv-loaded, reachable); Piper's is vaulted in 1Password and `op` timed out non-interactively until the user ran `eval $(op signin)`. `direnv exec .` per consumer repo is the clean way to get the token for GraphQL.
6. **Advisory-first is the settled pattern** for new gates (gap #2 and gap #3 both): report + Linear comment, no state change/block; hard sentinel gate documented as a fast-follow, kept out of CI-gated `bin/pk`.
