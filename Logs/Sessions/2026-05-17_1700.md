## Decisions / findings (worth remembering)

1. **Env-as-status (v2.5.0) was the right rename.** UAT became "PR open on preview"; `In <FirstEnv>` (e.g. `In Dev`) is the post-merge state; `Released` retired in favor of per-env `In <Env>` derived from `Ship environments`. The Linear board column now answers "which env is this on?" with no ambiguity. RS-Vault + Piper migrations both confirmed the model.

2. **v2.5.0.1 was a genuine bug, not over-cautious.** RS-Vault's first sync attempt (absolute-path invocation `bash ~/Projects/pipekit/scripts/sync-method.sh v2.5.0`) silently synced into Pipekit itself because `PROJECT_ROOT` was computed from the script's location, not `$PWD`. The fix: default to `$PWD`, refuse if cwd's git origin matches `METHOD_REPO`. ~20 spurious file rewrites in Pipekit's working tree before the bug was identified.

3. **The tier system was deliberately retired in v2.0.0 — but nobody completed the cleanup.** Config templates still document tier inference. The `templates/tier-{quick,standard,heavy}.md` files still exist. `/work`'s skill body explicitly says "No tier inference (Quick/Standard/Heavy gone)." Net: config promises behavior the code dropped. **Reviewer feedback + Piper logs both flagged this as the daily-loop pain point**: heavy gate-stacking on small WITs because there's no fast lane. v2.6.0 #1 is to wire tiers back in (Linear label → gate matrix) + restore Quick→runner dispatch.

4. **Empirical: cmux-orchestrated parallel-native shipping works.** 5 WITs (Piper Wave 0F cleanup, 2026-05-17) shipped in 75 min wall-clock vs 90-135 min serial estimate. 5/5 clean, 0 incidents, 3 audit-trail follow-ups filed. This is the bridge until v2.6.0 ships the proper tier+runner. The orchestrator prompt at `resources/cmux-parallel-native-batch-prompt.md` is the reusable template.

5. **`pk done --merge` regaining state-transition responsibility was right (v2.5.0 conceptual reversal of v2.3.0).** The original v2.3.0 strip-down rationale was "a worktree closing does not mean the issue is shipped" — but v2.5.0's UAT → In <FirstEnv> transition is a *narrower* claim than the v2.3.0-era "→ Done" that triggered the original concern. New mid-batch pain: pk done should ALSO write `02-<id>-SUMMARY.md` and flip the PLAN's `status: ready → shipped` so VBW's file-guard doesn't treat shipped plans as active. v2.6.0 candidate #2.

6. **30-day v2.5.0.1 pin is the right post-release discipline.** Reviewer feedback was "the framework just needs to stop oscillating." We shipped v2.4.x → v2.5.0 → v2.5.0.1 in three days; that's unsustainable. The pin holds Piper + RS-Vault on v2.5.0.1 for ~30 days while v2.6.0 candidates accumulate from real friction. Soft-drift caveat: docs-only additions on main (pipekit-cmux.md, silent-failure patterns, orchestrator prompt) accumulate in the pin window — consumers don't have them until next forward-sync. Acceptable for additive content; would NOT be acceptable for behavior changes.

7. **claude-review Draft-skip is a credit-burn win.** Piper PR #317 added `if: github.event.pull_request.draft == false` + `ready_for_review` to the trigger list. Expected reduction: 80-95% on heavy-iteration PRs (WIT-463's 23 commits → ~1-2 reviews instead of 23). v2.6.0 ships this as a `templates/ci/claude-review.yml` template so consumers inherit it.

8. **cmux RPC `surface.send_text` is broken; never use it.** Lifted from SiteLine 2026-05-17 findings. The RPC ignores its `surface` arg and routes to whatever is focused, then echoes the focused surface's id back so the call looks successful. Cost: ~1h debugging a load-test that fired into a different workspace. Documented in pipekit-cmux.md + pipekit-tooling.md (as the canonical "worst-class failure mode" exemplar for the Verify Library API discipline).

9. **cmux numeric input on Claude menus is ambiguous.** Empirically confirmed 2026-05-17 batch: sending `"6"$'\n'` to confirm "Chat about this" (option 6 visually) silently selected option 4 ("Use a VBW subagent"). Rendered "Type something" / "Chat about this" rows interleave with numbered options; numeric input clamps to the last "real" option. **Always use arrow-key + Enter from a master orchestrator.** Documented in pipekit-cmux.md.

10. **The Linear team-name placeholder pattern in handoff templates is fragile.** Piper's team name is `Withpiper`, not `Piper`. The 2026-05-15 handoff hardcoded `team: "Piper"` — empty MCP response wasted ~20 min until a session worker tried `Withpiper`. Fixed in `c501823` for the Piper handoff but the broader pattern (hardcoding project nickname as Linear team name) needs handoff-author discipline.
