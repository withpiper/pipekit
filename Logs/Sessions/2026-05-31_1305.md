## Decisions / findings (worth remembering)

1. **1M context + harness memory don't obsolete Pipekit's discipline** — the risk is *contaminated judgment, not lost memory*, so a bigger window doesn't relax stage isolation. The persistence layer those capabilities would gut was already pruned in the 4.7 cycle (NEXT.md, Stop hook). Enforcement is the durable value.
2. **`/pr-fix`'s old "only ≥80 survive, silence > noise" suppressed real findings at the find stage** — exactly the failure mode Anthropic's refreshed "Code review harnesses" 4.8 guidance warns about. Fixed coverage-first, then rebuilt as a two-axis model: severity (impact) and confidence (likelihood) kept independent, with an **INVESTIGATE** quadrant for high-severity/low-confidence.
3. **`pr-review-toolkit` (properly configured) ≥ `/pr-fix` on review depth.** `/pr-fix`'s durable edge is intent + cross-spec-scan + dedup + interactive fix + Linear/pipeline integration — not the review engine. So Phase 3 was made engine-pluggable (native `pr-review-toolkit` default, **fail-loud** if absent, `--engine=builtin` fallback), mirroring `/work`'s backend model.
4. **Single-pass LLM review is high-variance.** Same toolkit, same PR (#408): 0 Critical / 1 High (run 1, opus-4-7) vs ~4 Critical / 3 High (run 2, opus-4-8 + test agent + light priming). The most important security finding lived in that variance. Run 2× on high-stakes (`--runs=N`).
5. **`pr-review-toolkit` is Anthropic first-party** (`claude-plugins-official`, Apache-2.0, actively maintained). NOT carried by `sync-method.sh` → the native engine is a real plugin dependency; `builtin` is the portable path.
6. **Commit-format hook bug:** false-positives on multi-`-m` commits (validates the `Co-Authored-By` trailer, not the subject line).
