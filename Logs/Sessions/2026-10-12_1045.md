## Decisions / findings (worth remembering)

1. **Runbook ≠ plan.** The runbook is how to use Pipekit; the week's agreement is a dev-facing task list and lives in its own file. Only `/tpm` writes between the plan's `tpm:begin/end` markers; the runbook `Now` block is one pointer line. Linear wins any disagreement.
2. **A deferred write is an alert, not a memory.** `[tpm DATE] on-merge: <pk command> · <why>` on the issue; `pk done` prints it after the state transition and asks `Run now? [y/N]` only at a TTY with `PK_ON_MERGE` unset; otherwise print-only; it cannot fail `pk done`. First live test: `pk done PIPER-546`.
3. **Capacity is session-days.** Ethan runs three sessions on average, so `Weekly capacity days: 15`, with `Tier effort days: Quick 0.1 / Standard 0.5 / Heavy 1`. The SOP had summed serial effort against one number.
4. **Conversation rules Ethan asked for, now in the skill:** titles beside IDs everywhere; one question per turn (he missed a question buried in a list); a `Words:` gloss line; a plain-language read-back that states what is *not* changing.
5. **Carry the hand-written plan in the sync PR.** Syncing a repo whose plan exists only uncommitted would scaffold a skeleton that collides on the next pull; copying the three uncommitted files into the sync worktree made the sync report `OK … (owned by /tpm, not touched)` and gave Ethan one PR to merge instead of a commit plus a PR.
6. **Git refuses to overwrite an untracked file even when it is identical.** SiteLine `main` could not fast-forward while 29 session-log copies from a merged logs PR sat untracked — one of them with real local edits. Left for Ethan; he resolved it. Check `git ls-files --others` against `origin/<branch>` before promising a fast-forward.
