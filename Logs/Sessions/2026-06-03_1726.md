## Decisions / findings (worth remembering)

1. **Don't punt diff review to the human.** A gate that hands the user a raw `git show` is a defect — it asks them to perform the analysis the gate exists to do. `/verify`'s migration flag now spawns a review subagent and carries a Hold/Approve *verdict*; the human approves the verdict. Generalized in memory `feedback_no_diff_punting`.
2. **Auto-discover beats config for implicit needs.** `pk branch` nested env symlinks auto-discover real env files rather than reading a config list — because the failure mode that started it was that the need was *implicit and unconfigured*; a config list just reintroduces "forgot to configure it."
3. **`/light-spec` interlock bug (load-bearing, found by the live test).** `/light-spec` hardcoded moving the issue to `Specced`, but `pk spec-cycle`'s precondition is config-driven (`Spec ready state`). On a board without a `Specced` state (SiteLine's Piper-poc is `Needs Spec → Approved`), the cycle broke. Fixed: `/light-spec` publishes to the configured ready state (default `Specced`). The skill's own line 239 already stated this intent.
4. **cmux narration-watching footgun (earned live).** Watching a worker Claude by grepping `read-screen` for gate/verdict keywords false-fires on the worker *narrating its own plan* (fired 3× before turn-end detection worked). Detect turn-END (live present-tense spinner gone), or wire Stop/Notification hooks to `cmux notify`. Now in `pipekit-cmux.md`.
5. **`/pk-express` is a skill, not a Workflow.** It's sequential + human-gated, and a portable methodology can't depend on the plan-gated Workflow primitive. Workflow's place stays the *batch* layer (`/06-linear-todo-runner`), still gated on the worktree-isolation test.
6. **Push-auth root cause.** pipekit's `origin` was SSH → resolved to personal **Ethros19** (no withpiper access); switched to HTTPS so the keychain authenticates as **ethan-piper**. Underlying: dual GitHub accounts the user wants to consolidate — `ethan-piper` is the *sole* withpiper org owner + holds 2 personal repos, so the merge needs an ordered migration (memories `pipekit_push_auth`, `pipekit_account_consolidation`).
7. **Live validation proved the autopilot's key safety property** — the tier guard *refuses* heavy work (POC-14's section/subsection half needs a migration + RLS change → correctly held). That's the thing you'd most fear an autopilot getting wrong.
8. Piper-poc Linear workflow has **no `Specced` state** (`Needs Spec → Approved`); Quick items route straight to Approved (spec-skip).
