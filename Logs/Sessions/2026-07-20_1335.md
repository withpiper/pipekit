## Decisions / findings (worth remembering)

1. **Gate on filled-in config values, never the bare heading.** The phase-label layer's template ships its section commented out; a "has a `### Phase Label Layer` section" gate false-triggers on every verbatim template copy. Caught once by me mid-build and once more by the adversarial reviewer in summary prose — the correct phrasing had to be swept into *every* restatement, not just the operative one.
2. **Adversarial review on the v4.14.0 base feature earned its cost** — 4 real findings (gate wording regressions, a dead `Roadmap source` config key + a root-vs-`.vbw-planning/` path ambiguity it resolved, an over-claimed write surface in linear-hygiene, a saved-view coverage caveat). All fixed pre-merge.
3. **Stamp bumps without body updates are the drift the stamps exist to catch — and we did it twice.** GUIDE.md's `/roadmap-review` health-check list missed both new phases across v4.14/v4.15 despite two stamp bumps; the user's "did we update the paperwork?" audit caught it → v4.15.1. Same class again at v4.16.0: my first Never-do convention draft named headings that would have made `/work`'s own WIT-451 example non-compliant — fixed pre-merge.
4. **Skills_SOP's own high-stakes standard was under-applied to its own worked example** (1 of 5 skills had `When NOT to use`, 0 of 5 had `Common Rationalizations` — including `/verify`, the SOP's example). Near-equivalents are not equivalents: a scope fence ≠ redirect anti-criteria; `/work`'s Anti-rationalization guard targets Claude, not the user.
5. **Never-do rule adopted (user emphasis):** every guardrail line must be an actually-corrected mistake with its anchor (WIT-451, POC-382, RS-64 pattern) — "a Never-do without a real incident behind it is a guess dressed as a rule." Now a Skills_SOP requirement.
6. **The `/verify` Flag-check-F sentinel write is load-bearing** for v4.17.0: F embeds the security gate and auto-rolls into `pk ship`, so without F writing `secgate-complete.md`, every categories-armed project would refuse right after its own gate passed.
7. **Sentinel-gate design:** sentinel on *every* PASS including no-category-matched (`pk ship` can't classify — the sentinel proves the classifier ran clean at this HEAD); FAIL writes nothing (the missing sentinel *is* the block); one shared pure `pk_gate_verdict` serves both gates (bypass-env > skip > ok > bypass-force > block).
8. **Distribution bug found by proximity:** `check-no-self-references.sh` — invoked by `pk verify`, documented as synced — was never in `sync-method.sh`'s script list. Consumers enabling `Self-reference check` got a silent skip. Fixed as a v4.18.0 rider.
9. **Remote drift check = the tool's own refusal.** `supabase db push --dry-run` *is* the authoritative disk-vs-history check; parsing `migration list` output would be fragile across CLI versions.
10. **Smoke-fixture gotchas:** promote E2E needs `push -u` (step 1 does a tracking `pull --ff-only`) and a trivially-green `## Pre-Deploy Gate` (cmd_verify returns 1 when the section is absent); `(cmd | tail)` captures tail's rc, not the command's — my own debug bug.
11. **External 9-point skill rubric: adopt selectively.** Took the two strongest items (Never-do anchoring, good/weak example pairs); rejected uniform 9-section structure — it would bloat low-stakes skills, which Skills_SOP already warns against.
12. **SiteLine port checks that paid off:** all four target skills byte-identical to the last tag (no local edits to clobber); "WOULD UPDATE" noise was stale local `skill.json`s + the known release-changelog override; sync nudges but never rewrites `method.config.md`.
