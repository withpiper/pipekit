## Decisions / findings (worth remembering)

1. **Advisory-first, hard-gate-later** was the chosen enforcement posture (user picked it). The hard sentinel gate stays out of CI-gated `bin/pk` for now — documented as a fast-follow in `Production_Readiness_SOP.md`. Rationale: ship the discipline + report shape, learn from real runs, only then wire a blocking gate.
2. **`/prod-ready` mirrors `/financial-review`'s portable-framework pattern:** discipline + report shape live in the skill; the *concrete* checks live in a per-project `resources/prod-readiness-checks.md` (scaffolded from `templates/prod-readiness-checks.template.md`). The gate is a **no-op without that checks file** — so each consumer must opt in after sync (sync never touches `method.config.md`).
3. **The commit-hook nudges had two distinct root causes**, only one of which was the hook's own bug. (a) The hook matched `git commit` *anywhere* in a command, so `grep -m1 "git commit"` extracted `1` as a "subject" — fixed by boundary-anchoring (real invocation = command-initial or preceded by `;&|(){}\`` or newline). (b) The nudges actually *seen in-session* came from the **stale VBW plugin's** Bash PostToolUse hook running the OLD validator — the plugin was disabled mid-session (A2) but hooks don't unload until restart. This is why purging the plugin mattered beyond tidiness.
4. **VBW plugin is fully purged** from the machine (~33M reclaimed, 0 artifacts, registry clean, other marketplaces intact). `claude plugin uninstall` failed twice (scope mismatch, then "not found" after marketplace-remove had already de-registered it) — resolved by directly `rm -rf`ing the orphaned cache + empty data dirs. Confirm purge with `find` piped to `wc -l`, NOT `find && echo` (find exits 0 regardless, so the echo always fires).
5. **SiteLine config callout was rotting:** a `> Status (2026-06-22): currently i1. → P1. Client Portal` blockquote in `method.config.md § Phase Surface` violated pipekit-discipline.md's "don't reference current state." Replaced with a stable "verify the live current phase with `pk status`" line (PR #440).
6. **Production boundary placement:** `/prod-ready` runs before the final `pk promote <last-env>` on multi-env; before merge to `main` / `pk done` on 1-tier (where `pk promote` is disabled).
