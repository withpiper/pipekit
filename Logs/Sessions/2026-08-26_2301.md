## Decisions / findings (worth remembering)

1. **A test that asserts on captured output can be structurally blind.** My first regression test for the `grep|sort|head` pipeline compared printed output — but both the fragile and robust forms print nothing on empty input, so restoring the defect reddened *zero* tests. The defect only shows in the exit status. Caught by mutation-testing, not by reading the test.
2. **bash suppresses errexit inside `$( )` but not for a bare call** (measured on 3.2.57, not assumed). So a pipeline returning 1 on empty input breaks some callers and not others. I initially wrote this up as a live bug breaking the remote fallback; it was latent, since both call sites substitute. Corrected in the CHANGELOG and the code comment rather than left overstated.
3. **Linear's `commentCreate` returns `success:true` for an empty body.** A heredoc body that failed to cross into an `op run` subshell posted at `len=0` and the API called it success. Assert on the echoed `comment.body|length`. Then compounded it by reconstructing the comment UUID from its 8-char display prefix — re-query for the full id instead.
4. **Substring id matching is a real collision risk.** `contains("PIPER-1")` matches a PIPER-10 ship record. The follow-up detector matches the exact header. A test that "passed" for the wrong reason surfaced this.
5. **The issue's own root-cause was slightly over-broad.** `pk_branch_issue_id` is prefix-agnostic, so `pk done` run *from* a `fix/` branch always worked — only the explicit-ID path was broken. Scoped the fix to two call sites rather than the whole resolution chain.
6. **A sync PR must not carry code edits.** piper's `claude-review` raised a nit (hand-rolled YAML subset parser in `pk_workflow_pr_branches`, from v4.31.x, advisory-only). Not folded in: a sync PR that edits code stops being byte-identical to its tag, which is the property that makes it verifiable.
7. **Clobber audits can be tested, not asserted.** `git worktree add /tmp/pk-<oldtag> <oldtag>`, then diff each consumer file at `origin/<base>` against the pristine upstream of the version it was on. For piper: all 34 modified files byte-identical beforehand → no customization existed to lose.
8. **Override drift is not reconstructable after a sync.** The sync refreshes `.upstream-snapshot`, so a post-hoc compare reads clean and lies. Capture DRIFT warnings during the run.
