## Decisions / findings (worth remembering)

1. **Pin discipline retired as load-bearing.** The v2.5.0.1 30-day pin was framed as "stop oscillating." User redirected: the oscillation was about churn (three releases in three days), not calendar cadence. A properly-batched 12-item release inside the window is the opposite of oscillation. Calendar pins are arbitrary; ship by workability. The `v2_6_0_backlog_and_pin_discipline.md` memory's pin framing should be considered downgraded.

2. **Retract-and-re-tag is a usable pattern when the window is short.** v2.6.0 was tagged at the 8-item release commit, then retracted ~5 minutes later when the user said "let's do a real big release." Re-tagged at the 12-item doc-scour commit. No consumer disruption because no consumer had synced in the window. The same pattern applied again ~hours later to move v2.6.0 from the release-commit (stale docs) to the doc-scour-commit (full v2.6.0 narrative). Lesson: tag late, after doc-scour, not at the first "release-class" commit.

3. **Doc-scour is genuinely part of every minor release.** I tagged v2.6.0 once and then had to re-tag it twice because each time I discovered another canonical doc that referenced pre-release behavior. The doc-scour added ~165 lines across 11 docs and was load-bearing for the v2.6.0 narrative — consumers pinning to v2.6.0 needed those docs to match the new bin/pk + skill behaviors. Lesson: bundle the doc-scour into the release commit before tagging, not after.

4. **#5 path-restriction decision made empirically.** Earlier candidate held on path-restriction question (allowlist vs all-paths with skip-on-trivial). User chose Option B (all-paths + skip-on-trivial) based on PR #331 evidence that claude-review caught bugs in non-high-leverage paths an allowlist would have excluded. Encoded in `templates/ci/claude-review.yml` triage job.

5. **v2.6.0 #14 (.envrc symlink) was half-broken on first ship.** Symlink lands correctly but direnv treats the worktree path as a new .envrc and blocks it. Same MCP-auth failure mode #14 was meant to fix. Patch v2.6.0.1 added `direnv allow "$wt_path"` after the symlink — propagates the user's existing trust decision (they already allowed the parent's .envrc, the symlink IS the parent's .envrc) rather than bypassing the security model. Fails soft when direnv isn't installed. Lesson worth carrying: when you symlink a file into a fresh git worktree, downstream tools treating that worktree as a separate workspace will re-evaluate trust on the symlink. Need to "ratify" the symlink as already-trusted.

6. **Ghost-applied migration pattern (the broken-beta window).** Piper has shared beta+prod DB. WIT-500 added DEFAULTs to `log_audit_event`; WIT-504 was the calling code that started omitting params. Both landed on dev → beta. The migration didn't reach `piper-prod` until the beta → main promote PR triggered `supabase-production.yml`. Window between beta-merge and main-merge = beta runs new code against old prod schema = audit-emission paths break (sign-in, sign-out). Two structural fixes: (a) schema-first sequencing — fire migration workflow on `beta`-merge not `main`-merge (one-line YAML diff); (b) backward-compatible-migration discipline — every migration must work with both old and new code. Pipekit recommends (a) in `sop/Git_and_Deployment.md` § Shared beta+prod DB; Piper landed the YAML change in parallel.

7. **The v2.6.0 #10 over-eager WIT-mention bug fired twice in 6 days.** WIT-416/490/491 trio refused by leap-frog guard on both PR #348 (2026-05-18 beta promote) and PR #357 (2026-05-24 main promote). Root cause: `pk_promote` parses commit messages for any `${prefix}-${num}` token, including cross-references in commit bodies ("see also WIT-490"). The leap-frog guard correctly refuses the bogus transitions, but the noise compounds with every promote. Recurrence argues for bumping #10 priority — was "defense-in-depth, no current pain" but now demonstrably ongoing pain.

8. **Commit message format is strictly enforced by PostToolUse hook.** Bare `docs:` without a scope is flagged. Always use `{type}({scope}): {desc}`. Saved to memory.

9. **`set -u` errors on empty array expansion.** Bit me mid-#6: `"${draft_args[@]}"` with `draft_args=()` errors out under `set -euo pipefail`. Refactored to explicit if/else branches. Pattern worth remembering for any future bin/pk additions that conditionally add args.

10. **Tag-move semantics: deleting and re-pushing a tag is fine for unpinned tags but destructive for pinned ones.** We retracted v2.6.0 twice with no consumer impact because the window was minutes and we knew Piper/RS-Vault hadn't synced. Don't make this a habit — set up the release commit + doc-scour + tag in one sequence so re-tags aren't needed.
