## Decisions / findings (worth remembering)

1. **The reviewer sits upstream of backend dispatch.** The Spec Review Agent / Linear Guidance run *before* `/work` is invoked, and `/work` plans inline in every backend — so the executor is irrelevant to the review. The fix was to name "the planner," not to swap VBW→native. Naming VBW was a category error even pre-3.0.
2. **Native raises, not lowers, the gate bar.** Native's task-DAG + atomic-commit-per-task + verify-before-integrate makes Decomposition Readiness and testable AC *more* load-bearing, so the spec-review gate logic was left untouched.
3. **Long-running sessions can hold a stale `origin/main`.** This session synced Piper + SiteLine to **rc2** while a parallel session had already cut **rc3** live. Caught only when reading `pipekit_3_0_status.md` (which correctly said rc3). Lesson now in memory: verify live tags (`git ls-remote --tags`) + PR numbers before syncing — PR numbers are monotonic, so #108–#112 being mine proved #113/#114 came later.
4. **rc2 tag re-pointed (force-tag, user-approved).** Because the README/GUIDE reframe (#112) landed after the rc2 release commit but carried the rc2 stamp, and nothing had synced rc2 yet, the `v3.0.0-rc2` tag was force-moved to include the docs. Verified `v3.0.0-rc2^{}` = the doc-merge commit.
5. **Sync dry-run has a self-update footgun.** Running `sync-method.sh --dry-run` in a checkout self-updates `scripts/sync-method.sh` in that working tree (not read-only). It left a stray `M scripts/sync-method.sh` in Piper's main checkout; reverted. Mitigation adopted: sync consuming projects in an **isolated `git worktree`** off `origin/<integration>`, never the active checkout.
6. **Piper repo disallows PR auto-merge** (`enablePullRequestAutoMerge` off) — #447 needed a manual merge after CI. SiteLine allows it.
