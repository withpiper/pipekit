## Decisions / findings (worth remembering)

1. **Pilotfish verdict:** its core thesis (tiered model dispatch, fresh-context verification) was already Pipekit practice; the transferable idea was role indirection — model names live in one config row, skills cite roles with inline defaults (absent section = zero behavior change). Escalate-on-failure deferred until the policy has mileage; grounding-to-haiku was initially deferred, then folded in with the `/work` spawn-site sweep (`e6e7179`).
2. **The "Fable 5 mega prompts" post is better-grounded than it looks but not trustworthy:** its "operating rules" template is lifted from Claude Code's own system prompt / Anthropic's migration-guide snippets (never copy into skills — the harness already injects them); "'explain your reasoning' trips the refusal classifier" overstates the real `reasoning_extraction` category; the benchmark numbers (SWE-Bench 80.3%, "3× memory") are unverifiable; the pricing/effort claims check out.
3. **No `fable` in the Model Policy, deliberately:** 2× Opus cost with no capability need in bounded subagent lanes, and Fable's cyber classifiers land exactly on Pipekit's security-review gates (refusal risk on the content those gates exist to examine). A consumer can opt in per-role with a one-row config edit — that's the point of the indirection.
4. **`/work` was the big session-model leak:** it passed no `model:` at any spawn site, so on a Fable session every atomic task agent ran at frontier cost. Now: task agents → execution (sonnet/medium), explorer → grounding (haiku/low), spec validator + security review → plan-review (opus/xhigh).
5. **`pk done --merge` redundancy root cause was prose, not `bin/pk`:** the binary's hints were already merge-state-aware; the parroting came from `/pk-exit`'s template and doc examples (SiteLine's POC-343 log prescribed `--merge` for an already-merged PR). Fixed at the sources sessions actually read.

7. **Release-folding over version proliferation:** the `/work` pins could have been v4.14.0, but PR #147 was unmerged/untagged, so they folded into v4.13.0 — one consumer sync, no divergence window between the policy table and behavior.
