4. **R5 fix: don't `2>/dev/null` a user-facing read's fetch.** First cut swallowed `pk_linear_gql`'s "API key not set" error, so the no-key path exited 1 silently. Under `set -o pipefail` the gql exit-1 propagated; removing the suppression surfaces the real error. Daily-loop reads suppress+file-fallback, but `pk issue show` has no fallback → must surface.
5. **`pk issue show` design: fat fields fetched only on demand + symmetric comments trigger.** `description` via `--fields description`; `comments` via `--comments` OR `--fields …,comments` — the symmetry prevents a field request rendering a false "(0)". Pure renderer (`pk_issue_show_render`) split from the fetch so it's unit-testable with no network.
6. **Chose to fold R5 into v4.19.0 rather than trail it.** Folding meant correcting the now-false "no bin/pk change / smoke 121 / R5 deferred" claims across CHANGELOG + 4 rolling blurbs, and tightening R1/R3/`/work` to name `pk issue show` first-class (the followup doc had pre-committed to that tightening).
