## Decisions / findings (worth remembering)

1. **CodeQL on private repos requires GitHub Advanced Security (~$49/active-committer/month).** Workflow PR #333 ran CodeQL analysis successfully (3 diagnostic messages) but couldn't upload — "Code Security must be enabled." Closed #333, pivoted to Semgrep (PR #335). **Semgrep is the realistic Pipekit default for private-repo consumers; CodeQL stays as the option for orgs already paying for GHAS.**

2. **Semgrep on this kind of PR finds nothing — and that's still useful.** On PR #331 (50-commit audit-logging promote): 0 findings across 1059 rules / 56 files / 54s. The PR's risk profile (RLS, SECURITY DEFINER, auth flow, financial logic) doesn't intersect with Semgrep's strengths (injection / XSS / hardcoded secrets / dangerous APIs). Semgrep earns its keep on different *kinds* of PRs (user-input handling, dep upgrades, pattern-heavy code). Free deterministic baseline; expect long silent stretches.

3. **claude-review (agentic GHA) caught 2/2 must-fix bugs on PR #331 that Gemini Flash + Semgrep both missed.** Load-bearing capabilities: `.claude/rules/` access (caught the project-specific `export default` rule violation) + cross-file pattern matching (caught `?actor=` UUID validation gap by comparing with the existing export-route guard). One bug was in a non-high-leverage path — argues against tight path-restriction.

4. **Gemini Flash quirks worth memorializing.** (a) `gemini-3.1-pro-preview` is paid-only on free tier (zero free quota); `gemini-pro-latest` auto-resolves to the same paid model. Use `gemini-flash-latest` for free-tier work. (b) Gemini 2.5+ Flash uses internal "thinking tokens" that count against `maxOutputTokens`. On first run, 15.7k of 16k output budget went to thinking + 654 visible tokens → truncated mid-finding. Fix: bump `maxOutputTokens` to 65536 + add `thinkingConfig.thinkingBudget`.

5. **OpenAI API has no free tier — needed $10 prepay to run the Codex test.** Friction factor on "just try it" experiments. Gemini's free tier gave us same-day access; OpenAI required billing setup first.

6. **Codex-branded models require `/v1/responses`, not `/v1/chat/completions`.** First call attempt returned "not a chat model" error. The Responses API has different request/response shapes — codex-branded models are designed for the agentic-style endpoint.

7. **Codex review quality is roughly comparable to Claude — "ship faster via Codex" hypothesis NOT supported by data.** On PR #341 head-to-head: each caught 1 unique substantive item the other missed (Codex got the UUID validation gap claude-review missed in this PR; claude-review got a subtle test-assertion mismatch Codex missed). Both caught the same two headline issues with different severity calibration (Codex more security-frame-alarmist; claude-review more architecturally accurate — recognized in-DB GRANT is the real gate).

8. **claude-review's "apply standard patterns universally" isn't 100% reliable across PRs.** Caught UUID-validation pattern violations on PR #331 (three of them in different files); missed the analogous case on PR #341. Real signal. Mitigations: run `/pr-fix --review` locally as second-pass, OR add a Semgrep custom rule for UUID validation on dynamic route params (deterministic backup).

9. **The OpenAI/Microsoft "IP-absorption pattern" is the actual rationale for vendor exclusion** — not vague "ChatGPT trust." Documented examples: ChatGPT itself emerged after watching GPT-3 API usage, Code Interpreter / Custom GPTs / Operator followed observed user patterns, GPT Store absorbed the OSS LangChain-style ecosystem within months, Copilot training corpus questions still litigated (Doe v. GitHub), Microsoft's multi-decade EEE pattern. The risk is organizational learning that no contractual guarantee covers. Captured as standalone feedback memory so it applies to future vendor decisions beyond v2.6.0 #5.

10. **The IP-absorption rule has a finite useful lifespan** — Anthropic carries lower-but-non-zero risk (heavy AWS/Google capital, potential M&A). Captured in the feedback memory: re-evaluation trigger is major M&A event in AI vendor space OR every 6 months, whichever first.

11. **User signal: "every WIT I ship spawns two — not sustainable."** Codified as feedback memory `feedback_no_followup_proliferation.md` with a decision table. Default rule: fold small/adjacent reviewer findings into the current PR rather than file follow-up WITs. Scope creep here is a feature, not a bug. Doesn't apply to methodology-level backlog like v2.6.0-candidates itself.

12. **Branch-filter on claude-review (base = beta/main) cleanly maps to user's mental model of "review at release, not workflow."** Day-to-day WIT shipping (feature → dev) bypasses; promote PRs (dev → beta, beta → main) auto-fire. Empirical validation end-to-end: PR #347 (dev-base) had no claude-review check; PR #348 (beta-base) fired claude-review which passed in 2m44s.

13. **`pk promote beta` working correctly — and the v2.6.0 #2 over-eager WIT-mention bug is visible in the wild.** On PR #348 promote: 8 WITs auto-detected from commit bodies; leap-frog guard correctly refused 3 (WIT-416/490/491 in Ideas/Specced — cross-references not actual shipped work). 4 already at Done (skipped). 1 successful transition (WIT-497 Parked → In Beta — worth sanity-checking whether Parked-class should auto-promote).
