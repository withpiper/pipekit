## Decisions / findings (worth remembering)

1. **The fallback was doubly dead.** It required *both* `PHASES.md` and `linear-map.json` present to return anything (`bin/pk` gated on `[ -n "$fname" ] && [ -n "$fproj" ]`). `PHASES.md` alone yielded nothing. Combined with neither consumer having the directory, it had zero reachable code paths.

2. **`pk portfolio` carried a redundant Linear round-trip.** Its file-fallback branch called `pk_phase_context`, which re-queried the API — but the caller had already derived `nat` from `pk_native_phase_context(init_json)` on the same payload. The fallback could only ever return what was already in hand. Found while cutting, not while looking for it.

3. **`/spec-preflight`'s phase-detect probe could only ever fail.** It resolved through `.vbw-planning/scripts/` and the plugin cache; post-retirement both are absent, so it emitted `⚠ phase baseline unverified` on *every* run and the skill documented that as "expected." A permanently-noisy line masquerading as graceful degradation. Removing it took Step 2 from five claim categories to four.

4. **`resources/v2.6.0-candidates.md` was not purely historical.** Archived it as a dated backlog doc, which broke two *live* citations — `templates/ci/README.md` and `skills/pr-fix/SKILL.md` both cite its "Why OpenAI/Microsoft are disqualified" section, which is current vendor-IP policy. Repointed to `archive/` rather than reverting the move. **Lesson: a doc's age doesn't tell you whether it's load-bearing — check inbound citations before moving anything out of the live tree.**

5. **Measuring drift-check against a stashed baseline caught a real regression.** Assumed the 31 errors were pre-existing; stashed and re-ran on clean `main` to confirm (32/67 → 31/66, a net *reduction*). Later the archive moves pushed it back to 32 — the finding-4 broken citation. Without the baseline number the regression would have read as noise. Per `pipekit-tooling.md` § "The Verification Method Must Be Able to See the Failure."

6. **`.claude/hooks/` is tracked; `.claude/skills|rules|agents` are gitignored.** Not uniform. The regenerated `validate-commit.sh` mirror would have been left as a stray working-tree change after committing — caught it and amended into the release commit.

7. **User corrected my keep-recommendation on the Cmux anchor.** I'd recommended preserving `sop/Cmux_Orchestration_SOP.md:15` verbatim (it quotes a 2026-05-17 menu). User flagged that it cites a skill/path a reader can no longer find. Genericized the option identity, kept the incident (sending `6` selected option 4). **Anchors should name the mechanism, not the transient thing it happened to hit.**

8. **`Backend` removal was a real fork, worth asking.** Options were full removal vs. a value-agnostic guard that keeps the stale-config catch without the brand. User chose full removal — both consumers are already `native`, so the guard had done its job. A leftover `Backend:` row in a consumer config is now inert.
