## Decisions / findings (worth remembering)

1. **"phase" has 5 senses; only one maps to Initiative.** Roadmap-phase prose → initiative; but `/phase-plan` (skill name), `phase-detect`/`phase-slug` (identifiers), **`Future Phases`** (a literal Linear *workflow state* name — renaming = reconfiguring every board), `sub-phase` (= a Linear **Project**, NOT "sub-initiative"), spec-preflight "Phase 3.6", and generic skill-process "phases" were all deliberately kept. A blind find-replace would have corrupted four of the five.
2. **Sweep method: 11 low-cost (haiku) subagents over disjoint files against one locked decision map, deferring ambiguous cases back for human reconciliation.** Judgment stayed with the main session; volume went to haiku. Two misses caught in reconciliation: a partition gap (STARTUP.md unassigned) and a half-completed concept rename (agents conservative on "Phase Surface"), plus one over-reach (an agent coined "sub-initiative" in 4 spots).
3. **linctl's guarded-write pattern was worth stealing; the tool itself was not.** Adopted the pattern (pin token to workspace, fail on mismatch) into `bin/pk` with zero new dependency. Deliberately softened linctl's strict no-bypass: pipekit **fails closed only on a confirmed mismatch, fails open (warn) when Linear is unreachable**, because `pk` is a daily driver and a transient hiccup must never false-block the loop.
4. **Guard design:** runs at the single `pk_linear_gql` chokepoint, fired only when the query is a `mutation` (reads untouched + future mutations guarded for free). Pins on Team ID (globally-unique UUID) or, fallback, Workspace slug vs org urlKey. Pure `pk_linear_guard_verdict` split from I/O for unit-testing. Live-verified against SiteLine: legit token → `ok`, foreign UUID → `Entity not found`.
5. **Customize synced skills via `.claude/overrides/`, NEVER in-place.** SiteLine's `/piper-help-audit` row was edited directly into the synced `release-changelog/skill.md`, so every sync clobbered it. An orphan `security-review` upstream-snapshot (no override file) revealed the same pattern had happened before — that one was fine (the enhancements got upstreamed into pipekit canonical, override correctly retired). [[siteline_synced_skill_inplace_edits]]
6. **Always base a SiteLine sync on `origin/main`, not the local clone.** Local `main` had diverged: origin was 8 commits ahead (POC-284 / PR #496), local had an unpushed `3cffef1c` deleting ~4.7MB of `Assets/`. User chose to keep it (rebase).
7. **SiteLine `main` is branch-protected** (`tests-required` runs only in PR context) → no direct push; everything goes through a PR + auto-merge. The RLS tenant-isolation suite is **flaky** ("invalid response from upstream server" = transient Supabase gateway) — a re-run clears it; auto-merge stays armed through the re-run.
