## Decisions / findings (worth remembering)

1. **Case-insensitive filesystems hide a case bug from every filesystem probe.** `ls skills/*/skill.md skills/*/SKILL.md` matched both for one file; `[ -f ]` can't distinguish either. Only `git ls-files` (tracked case) and `ls | grep -x` (on-disk case) tell the truth. The doctor's "3 lowercase skills" was the listing symptom, not the census — upstream was 35/35 lowercase.
2. **A case-only rename doesn't propagate through a copy-based sync.** rsync/cp onto a case-insensitive checkout keeps the old name, and git with `core.ignorecase` doesn't even see a disk-level rename — the fix must be an explicit `git mv` in the consumer's index, which is what the sync now does. Harness-proven (dry-run announce / staged `RM` / idempotent / legacy lowercase override still applies via basename normalization).
3. **Compression is drift detection.** Rewriting CLAUDE.md's `/security-gate` row exposed a stale claim that plain `--force` waives the gate — wrong since v4.20.0's flag split. Dense history-laden prose had hidden it.
4. **Pin at the consumer's version, not the template's.** SiteLine's live `migration-drift.yml` was on `checkout@v7`; the template pins v6's SHA. Applied the v7 SHA — re-applying a template pin verbatim would have silently downgraded the action.
5. **Concurrent sessions on one repo duplicate work.** The SiteLine doctor session committed its own pk-exit/concept/define casing renames while this session's sync PR did the same — local main ended 2-ahead/6-behind with duplicate commits. Resolution pattern: prove subsumption with a path-scoped `git diff main origin/main` (empty) + `git show --stat` (pure renames, 0/0), then `reset --hard` with user confirmation.
6. **zsh `=`-expansion gotcha:** an unquoted `====` separator after `echo` dies with "=== not found" (zsh expands leading-`=` words as command paths). Quote separators in inline scripts.
7. **`gh pr merge` is classifier-blocked in auto mode** — merges stayed a human action all session (user ran them via `!`), which happens to match both consumers' merge policies anyway.
8. Canonical rules live in `templates/rules/` — pipekit's own `.claude/` is gitignored (its rules/skills copies are local dogfood, not the sync source). Edited the local copy first, had to mirror to the template; check `git ls-files` before assuming which copy is tracked.
