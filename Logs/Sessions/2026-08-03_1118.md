3. The new `Lane map URL` config key follows the plain-row precedent (`Financial review WIT`, `Migration dir`), not the commented-out `Skip rules` pattern — that pattern is reserved for keys that change *sync behavior*, not values a skill reads at runtime.

5. Piper's PR #561 was merged **on explicit user instruction**, not on my own initiative — the standing "Piper disables auto-merge, don't circumvent" default governs unprompted judgment calls, not a direct request to merge.
6. Found that the Bash tool's cwd resets to the pipekit repo **between every call**, not just across turns. A `gh pr create` / `gh pr merge` issued without a `cd` in that same call silently targeted the wrong repo and threw a confusing error ("head branch main is the same as base branch main"). Now: always `cd` + verify (`git branch --show-current`) inside the same call as any repo-dependent action.
